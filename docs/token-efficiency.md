# Token 消耗优化

本轮实施用户确认的方案 1、2、4、5。没有设置每日额度、请求配额，没有改变回复概率、气泡数量、模型输出上限或普通聊天的多轮历史长度；没有合并回复对象判断和生成回答。

## 同一个 Agent，不同任务视图

- 普通回复继续携带真实 user/assistant 轮次、已有摘要和本轮工具结果。
- 关键词、回复对象判断和摘要调用使用调用方已经准备好的资料，不再额外注入整段历史。判断仍参考最近六条消息；摘要仍使用已有摘要与待归纳消息。
- 主动分享先读取最近八条真实对话与长期摘要，必要时通过 `recall_chat` 查询本群更早的偏好和话题。新闻任务只携带当前采集资料。所有调用仍属于该聊天原有 Agent，原文记忆不删除、不跨聊天共享。
- 多模态消息与同一条纯文字历史匹配时保留图片，避免再叠一份相同历史。

## 暖场唤醒

原实现已有签名去重，但签名包含机器人自己的发言，可能让分享再次触发判断。现在只有新的人类消息、相关设置/角色/模型变化、日期变化或模型预约的时刻才重新判断。收到新消息时不必等待预约时刻。

Agent 返回 WAIT 时可以附带正数 `recheck_after_seconds`，仅在有时间依据时预约重查；未提供则等待事件。不强制新的固定暖场间隔，不改变手动推送入口，也不靠调用额度阻止工作。已有网络失败退避继续生效。

## 提示词与资料

保留角色、人设、称呼、安全、自然聊天、语音、账号昵称和气泡规则，合并重复表述。固定角色和规则放在提示词前部，称呼对象、时间和检索资料放在后部，以保留稳定前缀。

网页、视频描述和字幕在本地去重并按查询选择原文片段，不额外调用 AI 做压缩；不把搜索渠道逐项诊断反复交给模型。网页原文仍写入本地知识库，模型看到的是注明节选的资料，可以继续检索。图片仍直接进入原 Agent 多模态请求。

## 缓存统计

兼容 DeepSeek `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens` 和兼容接口的 `prompt_tokens_details.cached_tokens`。有真实缓存字段时记录到原日志及 SQLite Token 统计；未提供则保留 NULL（未知），旧记录不回填为虚假的零。

缓存命中属于输入 Token 的一部分，不能再次加到总 Token 中，也不能从总 Token 中减掉。日志中的总量仍是输入加输出。缓存主要影响费用；命中率和实际节省取决于服务商，稳定前缀不能保证每次命中。没有按照未经核实的单价自动估算金额。

迁移只在原 `token_usage` 表增加两个可空字段，保留旧消息、摘要和统计。修改前已保存源码和一致性数据库备份。实际每日节省应在相近聊天活动量下对比，而不能用固定样例的字符缩减比例充当每日 Token 节省率。
