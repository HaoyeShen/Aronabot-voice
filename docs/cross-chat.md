# 跨聊天记忆与管理员发送

## 记忆开关

进入「测试对象」（原监听对象），编辑对应群聊或好友，勾选「参与跨聊天记忆」。只有双方都开启的会话才能互相参考记忆；关闭后后续请求立即不再读取该会话。新安装默认关闭；各聊天仍有独立 Agent 和完整多轮历史。

共享内容为已保存的近期群友发言及较早摘要，带来源和发言者标记，按近期活跃程度选取，合计最多约3600字。只提供背景事实，不合并角色身份或执行任务，不额外调用模型。管理员验证消息、管理员私聊操作、原始XML和凭据不共享；朋友圈日记和评论不从这里读取其他群的原文。

## 管理员私聊发送

1. 在「设置 → 管理员指令」将管理员的微信昵称或稳定微信身份加入名单，并开启「允许名单内管理员私聊跨聊天发送」。
2. 管理员在**私聊**直接发送自然语言操作指令，无需 `/admin` 或密码。程序按实际发送者和管理员名单识别，由该私聊原来的 Agent 处理，不受普通消息3%抽签影响。管理员私聊无需另加监听白名单。
3. 指令同时写清目标全名/备注和完整发送原文，例如：`向test群发送：各位晚上好。` 或 `给张三发送：明天九点见。`
4. Agent 调用发送工具并读取实际结果，再在管理员私聊回复。只支持文字，沿用当前气泡字数和数量设置。正文不明确时请补充完整原文，工具不会猜收件人或把其他聊天内容当作授权。
5. 若进入了手动管理会话，发送 `/end` 后按原管理指令退出；撤出名单、关闭功能、原消息过期或停止机器人会使后续操作失效；/end仍用于退出手动管理会话，私聊名单身份由名单本身决定。名单内成员在重启后仍可直接私聊发命令；群聊管理指令保留密码验证。

目标可以不在监听白名单中，但必须通过本地联系人库**唯一精确匹配**昵称/备注；重名、模糊匹配、未找到会话均不发送。指令不能由群聊、共享记忆或网页授权。每条原指令对每个目标持久记录一次收据，发送结果未知时不自动重试；需要重试请先确认微信，再发新指令。

接入模型仍按同一私聊Agent记录工具调用、输入输出及结果。目标中的成功发言也写入该目标的助手上下文，用于后续对话和去重。

## 入站回复新逻辑

「监听与回复 → 先概率、再模型决定是否回复」默认开启：持续监听并保存上下文，**@和已确认的连续追问直接回复**；其余消息（包括单纯名称/关键词）先抽概率，默认3%，仅命中才由模型决定是否回复。模型拒绝、判断无效或接口失败时不发送。确认续聊仍沿用连续5条无关消息/可设置超时退出规则。

每群或好友可以在「测试对象」独立调概率；全局群聊概率可在「监听与回复」修改。关闭新模式恢复旧的名称唤醒方式。定时新闻、日记和主动分享保留各自调度。
