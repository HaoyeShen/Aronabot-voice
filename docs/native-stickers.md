# 微信原生动画表情

「监听与回复 → 回复行为 → 允许微信原生动画表情」默认开启，仍受「允许使用表情包」总开关控制。需要开启Agent并接入支持图片理解的模型。这里的动画表情是微信表情面板中的整张贴纸，不是Unicode emoji、[微笑]小表情或普通图片附件。

同一聊天Agent在确实适合语境时读取完整目录：收藏页及全部已下载、未移除的商店表情包页，不只第一页。目录从微信本地数据库取得，排序和表情标识可核对；特殊互动/管理项没有固定图片MD5时明确标为不可用。新装表情包会在下次读取目录时出现。

模型比较所有页面的候选，再通过预览工具读取具体候选的真实画面；每次可看1至3张，动画用按顺序排列的抽样帧，不冒称完整观看。预览直接回到原Agent，不另开描述模型。最终模型给出一张已预览表情、简短的语境理由及Q版手绘/官方立绘画风判断；无合适内容就正常聊天，不随机抽原生表情、不为使用而使用。不把完整图库塞进每条日常回复。

发送先核对目标会话与前台窗口，保持用户草稿；按住Alt→按E→松E→松Alt打开面板，不依赖工具栏位置，兼容全屏。选择已核实的包页和唯一表情图片按钮；必要时在该页有限滚动。随后只提交一次，并用本地消息类型及具体MD5确认发出的是所选原生动画表情。结果未知不重复提交，也不冒充成功或改成普通图片。停止、过期、切换角色、开关关闭或目标会话变化时取消尚未提交的发送。

模型工具调用仍在日志与Agent页可追踪，不发送到微信。支持JSON、代码块和常见`<tool_call>`包装；无效协议不作为普通回复，气泡解析和文字/引用传输入口也会拦截内部指令。

## 验证

只读遍历原生各页：`.\.venv\Scripts\python.exe scripts\verify_native_stickers.py`。端到端模型选择与发送：同一命令追加`--send`。脚本将目标硬性限制为`test`，不会发送到其他会话。正常机器人不要与这类独立UIA验证脚本同时运行，以免争用微信。

当前本机已遍历收藏页和6个商店包，逐页读到16张商店表情；在test群由模型比较目录并预览后选择“好耶”，已核对真实原生消息类型和MD5。
