# 每聊天独立的统一 Agent

每个微信群聊、私聊有各自的 `ChatAgent`，以微信会话身份标识解析；群备注和原群名归到同一身份。没有微信身份时先按会话名称建实例，解析成功后沿用原 Agent 标识。不同聊天不会合并上下文、任务或推送历史。

同一聊天的入站事件、对象判断、回复与重写、联网/知识工具、记忆摘要、新闻、主动分享及语音是该 Agent 的任务或步骤。`AgentRuntime` 统一创建任务、调用模型、记录程序输入与回答，并传播任务上下文到有界执行线程。一次任务可以多次请求模型；它不是一次 HTTP 调用永久回答未来消息。后台退避、用户消息优先、超时、停止和迟到结果丢弃继续生效。

同一聊天的所有任务使用同一段原文多轮对话：`user` 提问、`assistant` 回答、`user` 补充或修改、`assistant` 承接回答。原始用户发言和真正发送成功的机器人回复保存在 SQLite，构造请求时按时间顺序还原成原生消息数组；不在助手回答前添加人物标签、任务状态，不再用此前 API 输入输出或草稿冒充聊天轮次。私聊保留原文，群聊仅给用户消息加实际发言者昵称以区分参与者。新闻成功发送后也记录为助手发言，后续可以直接追问。内部工具轮次留在当轮执行链中，任务日志用于排查，不作为历史聊天发言。

原文上下文数量沿用每群/全局的 `context_limit`，文字预算内保留取到的全部完整消息，不对单条原文按 1600 字硬切；超出预算时移除整条最旧消息，更早部分沿用已保存的对话摘要。`stale_reply_minutes` 只决定是否回复过期入站消息，不再让十分钟前的原文从续聊中消失。重启后从同一 SQLite 对话及摘要接回，不依赖进程内 API 缓存。切换角色时，旧角色发言标为他人历史资料，不能冒充当前角色的助手回答。清空上下文同时清空本聊天原文、摘要和 Agent 缓存。任务元数据的 `session_id`、`conversation_id` 归属同一聊天；`continuation_id` 仅用于特定发言者的待补充事项。接口诊断另有有界缓存，与多轮对话分开。

分享任务使用 `AgentRunner`，由模型选择查询、换词、审核候选和生成配文；工具只返回真实证据，不自行调用另一个模型。视频详情/字幕/封面、网页及图片、新闻事实在同一任务中交回模型。新闻保留 24 小时、各群去重、国服官方渠道及日期时态检查；测试新闻不写正式发送名额。多模态图片直接附到本任务的模型消息中，不先请求文字描述。

没有贴切内容可以等待。主动文字须引用本群近期群友消息中至少四字的真实话题依据，内容不能是机械暖场、喊人聊天、询问最近开心的事。文章、图片与视频必须来自工具真实返回的候选；图片必须已实际读取。模型不能通过输出任意地址、BV 号或动作绕过校验。

「Agent 对话」采用聊天气泡：程序输入在右侧，Agent 回答在左侧，工具请求/结果作为过程显示。选择聊天后默认连续展示该 Agent 的全部近期任务，不因新闻或分享另开一段会话；左侧任务列表仅用于筛选排查，点击「跟随最新」回到整段会话。可展开完整消息，或显示接口请求与原始回答细节。凭据脱敏，图片编码只显示摘要；不展示内部思考字段。页面保存的是有界的本机近期视图，清空视图不删除聊天记忆，完整模型文字仍由本机轮转日志记录。

界面里的「Agent 自主使用工具」控制普通回复的自主工具轮次，不关闭统一调度或记录。每群人格与默认人格仍分别配置；切换人格不改变聊天 Agent 的归属，但会隔离旧角色待办状态。

语音参考录音及角色模型只在本机使用，不随源码与发布包上传。采集网页截图只渲染正文，微信读取仍使用本地数据库，不截取桌面。
